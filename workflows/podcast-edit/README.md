# 🎙️ ポッドキャスト自動編集ワークフロー

録音した音声から「えー」「あー」などのフィラー、言い直し、ノイズを取り除き、編集済みの音声として保存する。

---

## 決定事項（2026-09-27）

| 項目 | 決定 |
|-----|-----|
| 自動化レベル | Phase C（手動）でカットの質を確認済み → **録音が入ったときだけ Claude を起動**（Apps Script が10分ごとに確認し、ルーティンを API で呼び出す） |
| カットの強さ | **しっかり**。フィラーに加えて、言い直し・噛み・繰り返しもカットする |
| 撮り直し | 同じ内容を言葉を変えて話し直したときは、**前のテイクを丸ごと消す**（2026-10-01 ユーザー依頼）。`find_retakes` が候補を出し、Claude が文脈で判断。消したものは毎回の報告に一覧で出す |
| 編集方式（2026-10-06） | **テキスト編集方式**。`prepare` が読める台本 `script.txt` を作り、Claude は消す部分を `{種類:…}` で囲むだけ（文字は書き換えない）。`apply-edit` が秒数のカットに変換し、残る文章 `kept.txt` を Claude が通読して確認する |
| 言い直しの扱い（2026-10-06） | ルールを1本化：**最後のきちんと言えた版だけ残し、前の試みは丸ごと消す**（前の版のほうが完成している場合だけ例外） |
| フィラー（2026-10-06） | 0.4秒以上・吃音・連続・文頭の言いよどみは必ず消す。短くリズムを作っているものは残してよい（Claude が判断） |
| 間に埋もれた声（2026-10-06） | 0.4秒以上の間を個別に再認識し、1回目に落ちた「あの」「うん」「はい」なども台本に出す（`〈間の声〉`） |
| モデル（2026-10-06） | ルーティンは **Opus**（ユーザーの指示） |
| 脱線トーク | 文脈で判断する。面白い脱線は残し、**本題と無関係でつまらない脱線だけ**カットする |
| 確認フロー | 確認は挟まず、**そのままカットして保存**する。ただし元ファイルは必ず残す。出力は **MP3 のみ**（カットログはドライブに置かない。2026-09-27 ユーザー希望） |
| 話者 | 基本は1人。対談が混ざる場合は、声質の違いで話者を見分け、相手の相づちや発言を誤ってカットしない |

## 自動化の仕組み

```
① 録音を「01.Podcast音声アップロード」に入れる
② Apps Script（Google 側・無料）が10分ごとに「01」を確認
③ 新しい録音があるときだけ、Claude のルーティン「ポッドキャスト自動編集」を API で呼び出す
④ Claude のセッションが /podcast を実行: セットアップ → ダウンロード → 文字起こし → カット候補（機械検出）
⑤ Claude が候補を見直し、言い直し・繰り返し・脱線を文脈で判断して cuts.json を作る
⑥ 編集（カット跡に間を入れる）→ ノイズ除去・破裂音対策・-16 LUFS
⑦ 編集後をもう一度文字起こしして、言葉の欠け・フィラーの残りを確認（必要なら直して⑥へ）
⑧ Apps Script 経由で「02.Podcast編集済み」に MP3 を保存、元ファイルを「処理済み」へ
```

- 手順とカット基準の正本: `.claude/commands/podcast.md`
- ドライブへの読み書きと録音の見張りは Google Apps Script（`apps-script/Code.gs`）が担当する
  - 理由: 今のドライブ連携（コネクタ）は大きいファイルを書き込めない。Apps Script ならあなたのアカウント権限で動き、Google Cloud の設定が要らない
- 1時間ごとの定期実行はやめた。録音がなくてもセッションが起動し、1回あたり API 換算で約0.4ドル分の使用量と、ルーティンの1日の実行回数を消費するため
- 反映までの時間: アップロードから最大10分＋処理時間（セットアップ込みで10分前後）
- 呼び出してから3時間たっても録音が「01」に残っていたら、処理に失敗したとみなして呼び直す（1ファイルにつき最大3回）

## 自動化のセットアップ（ユーザー作業）

### 1. Apps Script をデプロイする（済）
1. https://script.google.com/ で新しいプロジェクトを作り、`apps-script/Code.gs` の中身を貼り付けて保存
2. プロジェクトの設定 →「スクリプト プロパティ」に `TOKEN`（推測されにくい長い文字列）を追加
3. デプロイ → 新しいデプロイ → ウェブアプリ（実行ユーザー: 自分／アクセス: 全員）→ URL を控える

### 2. Claude の環境を設定する（済）
環境メニュー → Edit:
- ネットワークアクセス: **Custom**、許可ドメインに `script.google.com` と `script.googleusercontent.com`、デフォルトリストも含める
- 環境変数: `PODCAST_GAS_URL`（手順1の URL）と `PODCAST_GAS_TOKEN`（手順1の TOKEN）

### 3. ルーティンを API トリガーに切り替える
1. https://claude.ai/code/routines で「ポッドキャスト自動編集」→ 名前横のメニュー → **Edit**
2. 「トリガーを選択」で、**スケジュールのトリガーを削除**し、**API** のトリガーを追加
3. **Generate token** でトークンを発行してコピー（一度しか表示されない）→ 保存
4. ルーティンのオン／オフのスイッチを**オン**にする

### 4. Apps Script を更新して見張りを始める
1. Apps Script のコードを最新の `apps-script/Code.gs` に貼り替えて保存
2. スクリプト プロパティに `ROUTINE_TOKEN`（手順3のトークン）を追加
3. 関数の選択で `installTrigger` を選んで「実行」→ 権限（外部サービスへの接続・トリガー）を許可
4. 以後、10分ごとに `checkAndFire` が動く。実行ログは Apps Script の「実行数」で確認できる

## 技術メモ

- **文字起こしモデル**: `sherpa-onnx` + SenseVoice（日本語に対応し、1文字ずつのタイムスタンプが取れる）
  - Whisper はフィラーを省いて書き起こす傾向があるため、フィラー検出には不向き
  - huggingface.co は現在の環境のネットワーク設定でブロックされているため、GitHub Releases から取得する
- **ffmpeg**: apt ではインストールできないため、`imageio-ffmpeg`（pip）に同梱されているバイナリを使う
- クラウド環境はセッションごとにリセットされるため、毎回セットアップが必要

## テスト1回目の結果（260927_旅行のお土産、実はコスパいい説）

- 3:50 → 3:14（カット53箇所）。カットログは `episodes/260927/` にある
- SenseVoice は「え」「えっと」「あの」「まあ」を**文字として拾える**
- ただし、言葉と言葉の間（0.3〜0.8秒の隙間）にあるフィラーは1回目の文字起こしで見逃しやすい
  → **編集後の音声をもう一度文字起こしし、残ったフィラーや欠けた言葉を確認する**2周目のチェックが有効だった
- 1文字ごとの時刻は±50ms程度ずれるため、ぎりぎりでカットすると次の言葉の頭が欠ける（「冒頭」→「こも」など）。短いフィラー（「ま」1文字など）は無理にカットしない
- 元の録音がかなり小さかった（-38 LUFS）。約22dB持ち上げているため、ノイズが目立つ場合はマイクの入力レベルを上げて録るとよい

### v2 調整（ユーザーのフィードバック：「切りすぎて聞き取りにくい」）
- カットの跡を詰めずに、**0.22秒の間**を入れる（言葉同士がくっつくと聞き取りにくい）
- 長い沈黙・1秒以上のカットの跡は**0.5秒の間**を残す
- 0.3秒未満の「あの」「まあ」は、詰めずに**同じ長さの無音に置き換える**（テンポを変えずに音だけ消す）
- 「ま」1文字はカットしない（前後の言葉が欠けやすい）
- 結果: 3:50 → 3:29（v1は3:14）。録音の無音部分は完全な無音なので、間は無音で埋めて問題ない
- この設定を**標準**とする
