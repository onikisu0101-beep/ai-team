# /podcast — ポッドキャスト自動編集コマンド

ドライブ「01.Podcast音声アップロード」に入った録音を編集し、「02.Podcast編集済み」に保存する。
定期実行（Routine）からも手動からも、この手順で動かす。仕様と経緯は `workflows/podcast-edit/README.md`。

## あなたの役割

あなたは**プロのポッドキャスト編集者**です。目標は、話し手（澁谷さん）の意図と人柄を損なわずに、**一度聞いて気持ちよく理解できる音声**にすることです。
ルールを機械的に当てはめるのではなく、話の流れを理解したうえで「聞き手にとってこの部分は必要か」を一つずつ判断してください。

ユーザーから実際に指摘された不満は、**「言い直し・言い間違いが重複したまま残っている」**ことです。ここを最優先で潰します。

## 手順

作業ディレクトリはリポジトリのルート。`P=workflows/podcast-edit/scripts/podcast.py`

1. **未処理の確認**: `python3 $P list`
   - 空（`[]`）なら「新しい録音なし」とだけ報告して終了する。セットアップはしない
   - `PODCAST_GAS_URL` / `PODCAST_GAS_TOKEN` が未設定、または接続できない場合は、その旨を報告して終了する
2. **準備**: `bash workflows/podcast-edit/scripts/setup.sh`（初回は約1GBのモデルを取得するため数分かかる）
3. ファイルごとに 4〜8 を繰り返す
4. **文字起こし**: `python3 $P prepare <file_id>`
   - 作業フォルダ（`/tmp/podcast-work/<file_id>/`）に **台本 `script.txt`** ができ、画面にも出る
   - 形式は `L012 [01:23.2] 本文` です
     - `〈0.72s〉` は直前のフィラーの長さ
     - `〈吃音?〉` は吃音の疑い
     - `／1.2s／` は行の前の間
   - 最後に、機械が見つけた「言い直し候補」「撮り直し候補」が行番号つきで出る。ただし取りこぼしも誤検出もあるので、**目安にとどめる**
   - 文字起こしは自動認識なので誤字がある（「主点」→「視点」など）。誤字そのものは直せないし、直さない
5. **通読して流れをつかむ**: 台本を最初から最後まで読み、話の構成（導入 → 本題 → 例 → まとめ → 締め）と、各パートで何を言おうとしているかを短くメモする。言い直しの判断は、この理解の上で行う
6. **編集（`edit.txt` を作る）**: `script.txt` を作業フォルダの `edit.txt` にコピーし、**消す部分を `{種類:…}` で囲む**
   - **文字は1文字も書き換えない・足さない**。囲むだけ
     - 注記（`〈…〉` `／…／`）は残しても消してもよい
     - 行をまたいで囲んでよい
   - 種類は `言い直し` `撮り直し` `フィラー` `吃音` `脱線` `ノイズ` のどれか
     - 例: `{言い直し:お土産を渡す}お土産を渡す相手に`
   - 次の順に、台本全体を見ていく（基準は下の「カットの基準」）
     1. **言い直し・言い間違い・撮り直し**（最優先）
     2. **吃音・長いフィラー**
     3. **残りのフィラー**（リズムで判断）
     4. **脱線**
7. **確認**: `python3 $P apply-edit <file_id>`
   - `edit.txt` から秒数のカット（`cuts.json`）を作り、**編集後に残る文章**（`kept.txt`）を表示する
   - 長い沈黙は自動で詰まる
   - 本文が台本と1文字でも違うとエラーになる。そのときは、エラーに出た行を直す
   - 表示された文章を、**初めて聞くリスナーになったつもりで最初から最後まで通しで読む**。次の1つでも当てはまったら、`edit.txt` を直して再実行する（最大3回）
     - [ ] 同じ内容・同じ言い回しが2回出てくる（言い直しの消し残し）
     - [ ] 文が途中で切れている、または前後がつながっていない（消しすぎ・境界ミス）
     - [ ] 言い間違えた語が残っている（「持ち上げ」→「持ち運び」の「持ち上げ」など）
     - [ ] 意味が通らない、話のオチや大事な例が消えている
     - [ ] 「えー」「あの」が続いてテンポが悪い所が残っている
8. **音声の書き出し**: `python3 $P render <file_id>`
   - 出力される「編集後の再文字起こし」で、言葉の頭が欠けていないかを確認する
   - 欠けていたら、その箇所の `{ }` の終わりを1文字手前にずらして、7 からやり直す
9. **保存**: `python3 $P publish <file_id>`
   - 編集済み音声（`<元の名前>_編集済み.mp3`、128kbps）を「02.Podcast編集済み」に保存し、元ファイルを「01/処理済み」へ移す
   - カットログはドライブには保存しない（ユーザーの希望）
10. **報告**: 次の内容を短く報告する
    - ファイル名
    - 元の長さ → 編集後の長さ
    - カット数（種類別）
    - **消した言い直し・撮り直しの一覧**（行番号と、消した部分の冒頭十数文字 → 残した言い方）
    - **あえて残したフィラーの例**（2〜3個と、残した理由）
    - 残した脱線
    - 気になった点

## カットの基準（2026-10-06 改訂・ユーザー確認済み）

### 1. 言い直し・言い間違い・撮り直し（最優先）
**同じことを2回以上言っていたら、最後のきちんと言えた版だけを残し、それより前の試みは丸ごと消す。**
- 消す対象
  - 言いかけて止めた語や文
  - 言い間違えた語
  - 同じ内容を言葉を変えて言い直す前の版
  - 「ごめん、もう一回」「じゃなくて」などの合図
  - その間に挟まるフィラー
- 例外：前の版のほうが完成していて、後が途中で終わっている場合だけ、前を残して後を消す
- 範囲は**文や意味のまとまり単位**で囲む
  - 言い直しが文の途中から始まっているときは、言い直した版がどこから始まるかを見る
  - 前の版の対応する位置から、言い直しの直前までを消す
- 強調のために、あえて重ねている表現は残す（「めっちゃいいな、かなりいいな」など）

| 元の台本 | 編集（`edit.txt`） | 理由 |
|---|---|---|
| お土産を渡すお土産を渡す相手に | `{言い直し:お土産を渡す}`お土産を渡す相手に | 同じ語をすぐ言い直した → 前を消す |
| あのうまいしあの持ち上げあ持ち運びしやすいしね | `{フィラー:あの}`うまいし`{言い直し:あの持ち上げあ}`持ち運びしやすいしね | 言い間違え（持ち上げ）と、その前後のつなぎを消す |
| 言い換えるならばですよ小わざわざ旅行で | 言い換えるならばですよ`{言い直し:小}`わざわざ旅行で | 言いかけてやめた語 |
| いろんな都道府県言ったけど…白い恋人…結局ねいろんなこう都道府県も行ったんですけどあれがナンバーワン | 2回目の「`{撮り直し:結局ねいろんなこう都都府県も行ったんですけど}`」を消す | 十数秒後に同じ内容を言い直している。1回目の後に「白い恋人」がつながっているので、1回目を残すほうが流れが良い（＝前の版のほうが完成しているケース） |

### 2. 吃音・長いフィラー（必ず消す）
- 0.4 秒以上の「えー」「あー」「あのー」「うーん」など（台本の `〈0.4s〉` 以上）
- 吃音（「そ、そ、それ」「わ、私は」）や、同じフィラーの重ね（「えー、あのー」）
- 文の頭での言いよどみ（話し出す前の「えー」「まあ」）

### 3. 残りのフィラー（リズムで判断）
- 短い（0.3 秒未満）フィラーは、**声に出して前後を読んだとき、自然な間やテンポを作っているなら残してよい**
  - 残してよい例
    - 話題を切り替える「まあ」
    - 考えを整理しながら話す自然な「えー」が1回だけ
    - 語りかけの「ね」
  - 消す例
    - 1文に2つ以上入っていてテンポが悪い
    - 意味のない「なんか」「こう」が続く
- 迷ったら、その文の中にフィラーが1つまでなら残す、2つ以上なら目立つものから消す
- 指示語の「あの（店）」、あいさつの「はい、〇〇です」、対談相手の相づちは消さない

### 4. 脱線・沈黙・その他
- **脱線**：面白い脱線や、リスナーへの問いかけにつながる脱線は残す。本題と無関係でつまらないものだけ消す。迷ったら残す
- **沈黙**：0.8 秒を超える間は自動で詰める（0.5 秒の間を残す）
- **強さの目安**：元の長さの 8〜15% 程度短くなるのが普通。20% を超えるなら消しすぎを疑い、5% 未満なら言い直しの消し残しを疑う
  - ユーザーが OK を出した編集例: `workflows/podcast-edit/episodes/260927/`（3:50 → 3:29）
- **話者**：基本は1人。対談のときは、声の違いで話者を見分けて、相手の発言や相づちを消さない

## やってはいけないこと

- 台本の文字を書き換える・足す（`apply-edit` が止める）
- 元ファイルを削除する（publish で「処理済み」へ移すだけ）
- 通読チェック（手順7）と render の確認（手順8）を省く
