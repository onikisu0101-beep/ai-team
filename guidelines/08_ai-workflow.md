# AIチームワークフロー ガイドライン

## 概要
AIエージェントチームが効率的に機能するためのワークフローガイドライン。
全エージェントが理解すべきチームの動き方・情報の流れ・協働ルールを定義する。

---

## チーム設計の基本原則

### 原則1: 専門分担の徹底
- 1つの専門領域は1人のエージェントが担当する
- 自分の専門外の判断は、専門エージェントに渡す
- 「なんでも自分でやろうとする」はチームへの負荷になる

```
OK: 「英語コンテンツの内容はEmmaに任せる（Mysticが英語コンテンツを作らない）」
OK: 「データ分析はNovaが担当（SarahがNovaの役割を兼務しない）」
NG: 「Sarahが分析もコンテンツ作成も全部やる」
```

### 原則2: 生成と評価の分離（最重要）
- コンテンツを**作ったエージェント**は、そのコンテンツを**評価・チェックしない**
- 自己評価は品質管理として機能しない
- AlexはEmma・Mysticが作ったものを評価するが、自分では作らない

```
正しいフロー:
Emma → コンテンツ作成 → Alexへ提出 → Alexがレビュー
NG（禁止）:
Emma → コンテンツ作成 → 「自分でチェックしたので問題なし」
```

### 原則3: フェーズ分割の原則
大型タスクは以下のフェーズに分割し、各フェーズの成果物をファイルに出力する。
次のフェーズのエージェントはそのファイルを読んで作業する（コンテキストのリセット）。

```
Phase 1: 情報収集・方向性決定（Nova + Sarah）
         → 出力: content-plan.md
Phase 2: コンテンツ生成（Emma + Mystic 並列）
         → 出力: 各投稿の instagram-post.md / tarot-post.md
Phase 3: ビジュアル方向性（Aria）
         → 出力: デザイン指示書（各投稿に付記）
Phase 4: 品質チェック（Alex）
         → 出力: qa-review.md（投稿ごと）
Phase 5: 修正・最終化（各担当エージェント）
         → 出力: 修正済みコンテンツ
```

## エージェント起動の判断フロー

### タスクを受け取った時の分類
```
タスク受取（CLAUDE.mdの司令塔が判断）
    ↓
コンテンツ生成系？ → Emma（インスタ英語）or Mystic（タロット）
分析・データ系？ → Nova
戦略・計画系？ → Sarah（必要ならNovaを先に）
ビジュアル系？ → Aria
品質確認系？ → Alex
複合タスク？ → 下記の並列起動を検討
```

### 並列起動の条件
以下を満たす場合、積極的に並列起動を使う:
1. タスク間に依存関係がない（AのアウトプットをBが必要としない）
2. 各タスクが独立して完了できる
3. 全体の完成に両方が必要

**並列起動の例**:
- Emma（インスタ投稿作成）+ Mystic（タロット投稿作成）→ 並列OK
- Sarah（方向性決定）+ Nova（データ分析）→ 順序依存のため並列NG

## 情報の流れ（標準パターン）

### パターン1: 単一コンテンツ制作
```
ユーザー → 作成指示
    ↓
Emma or Mystic（コンテンツ生成）
    ↓
Aria（ビジュアル指示書作成）
    ↓
Alex（QAチェック）
    ↓
ユーザー（完成品）
```

### パターン2: 週次コンテンツ一括制作
```
ユーザー → 「今週分まとめて作って」
    ↓
Nova（先週データ確認）→ Sarah（今週方向性決定）
    ↓
[並列]
Emma（インスタ5本作成） + Mystic（タロット7〜8本作成）
    ↓
Aria（ビジュアル指示書一括作成）
    ↓
Alex（一括QAチェック）
    ↓
ユーザー（週次コンテンツパック）
```

### パターン3: 戦略改善
```
ユーザー → 「パフォーマンスが落ちている」
    ↓
Nova（データ収集・分析 → analytics-report.md に出力）
    ↓
Sarah（分析レポートを読んで戦略立案 → content-plan.md に出力）
    ↓
ユーザー（レビュー・承認）
    ↓
[並列]
Emma（インスタ改善コンテンツ作成）+ Mystic（タロット改善コンテンツ作成）
    ↓
Alex（QAチェック）
    ↓
ユーザー（最終確認）
```

## ファイル出力のルール

### 出力先の規則
| 種類 | 保存先 |
|-----|-------|
| 作業中ファイル | `_work/YYYY-MM-DD-[タスク名].md` |
| 完成Instagramコンテンツ | `output/instagram/YYYY-MM-DD-[タイトル].md` |
| 完成タロットコンテンツ | `output/tarot/YYYY-MM-DD-[タイトル].md` |
| 分析レポート（週次） | `analytics/weekly/YYYY-MM-DD.md` |
| 分析レポート（月次） | `analytics/monthly/YYYY-MM.md` |
| コンテンツプラン | `output/plans/YYYY-MM-[week/month].md` |
| QAレビュー | `output/qa/YYYY-MM-DD-qa-[連番].md` |

---

## エスカレーションのルール

### ユーザーへのエスカレーション条件（必ず確認を取る）
1. ブランドの方向性を変える判断が必要な場合
2. 新しいプラットフォームへの進出を検討する場合
3. グレーゾーンのコンテンツ（判断が難しい内容）
4. エージェント間で判断が分かれた場合
5. ガイドラインに記載のない新しい状況

### 緊急度レベル
| レベル | 状況 | 対応 |
|------|-----|-----|
| 🔴 高 | 公開済みコンテンツに問題発覚 | 即座にユーザーへ報告 |
| 🟡 中 | ガイドライン更新の必要性 | 次回作業時に確認 |
| 🟢 低 | 長期的な改善提案 | 月次レビュー時に報告 |
